# Shared ADS-B normalizer fixture

`backend/app/feeds/adsb.py` and `frontend/src/data/upstream.ts` normalize the **same** readsb
records into the **same** shape. They are two independent implementations of one contract: the
backend one serves the normal build, the TypeScript one exists only so the single-file build can
talk to the feeds browser-direct with no server (D-070).

Nothing made them agree. They agreed because they were written from the same notes, which is not
a property that survives either file being edited alone. **This directory is what makes the
agreement enforceable:** one set of inputs, one set of expected outputs, asserted by both
suites.

- `backend/tests/test_normalizer_parity.py` (pytest) asserts `adsb.py` produces `expected`
- `frontend/src/data/normalizerParity.test.ts` (vitest) asserts `upstream.ts` produces `expected`

Change either normalizer's behaviour and one suite goes red. That is the whole point — the drift
becomes a failing test instead of two screens that quietly disagree about an altitude.

## Files

| File | What it is |
|---|---|
| `raw-airplanes-live.json` | Verbatim `GET /v2/point/30.6944/-88.0399/250`, captured 2026-07-26 |
| `raw-adsb-lol.json` | Verbatim `GET /v2/lat/…/lon/…/dist/250`, captured 2026-07-26 |
| `raw-adsb-fi.json` | Verbatim `GET /api/v2/lat/…/lon/…/dist/250`, captured 2026-07-26 |
| `cases.json` | The fixture the tests actually read |

The three raw files are kept unedited alongside the curated cases so the provenance of every real
record can be checked, and so a future case can be pulled from real traffic rather than invented.
They also record the envelope difference first-hand: airplanes.live and adsb.lol answer `{"ac":…}`,
adsb.fi answers `{"aircraft":…}`.

## `cases.json`

Each case is `{name, provenance, synthetic, raw, expected}`.

**`synthetic` is the field to read first.** Eight cases are **real records** lifted verbatim from
the captures above — `on_ground`, military, LADD, the `alt_geom`-missing fallback, `alt_geom`
disagreeing with `alt_baro`, adsb.lol's missing `desc`/`ownOp`/`year`, and an adsb.fi record.

Ten are **constructed**, and say so, because the sky over Mobile during a single capture contained
no PIA contact, no negative altitude, no emergency and no position-less record. Those are built
from the documented contract in `docs/data-sources.md` §3.1 rather than observed. **The
distinction is recorded per-case so nobody later mistakes a constructed record for a measurement**
— the same reason CLAUDE.md ground rule 1 exists.

`expected` was generated by `adsb.py` and then **checked by hand against the documented contract**,
case by case, before being committed. That matters: generated-and-trusted would make the pytest
arm tautological — it would assert only that `adsb.py` still does what `adsb.py` did. It is
committed as reviewed data, and it is the oracle for both sides.

## Refreshing

Re-capturing is fine and occasionally useful; **regenerating `expected` from a normalizer is not**,
unless the contract itself changed and you have re-checked every value by hand. If a test goes red,
the question is "which implementation is wrong", not "how do I update the fixture".
